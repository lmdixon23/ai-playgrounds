# AI Playgrounds v1.9 canonical source R0

Status: first bounded implementation step for issue #47.

## Purpose

R0 creates an explicit current product model and a byte-locked build facade without replacing any historical release layer yet.

This is intentionally additive. The public artifact must remain exactly the frozen v1.8.1 product while source ownership becomes machine-readable.

## New current architecture surface

### `src/product/release.json`

Declares the current product boundary:

- v1.8.1 public software identity during equivalence work;
- exact frozen pre-refactor source SHA;
- 58 public files;
- 15 applets;
- 13 Foundations/course-track labs;
- 2 Modern AI extensions;
- EN/ZH/VI/ES learner locales;
- 15 active Quick Assigns;
- NN-1 and CNN-1 Level-2 pilot packs;
- offline and analytics privacy contracts;
- current build facade and byte oracle locations.

### `src/product/labs.json`

Declares all fifteen labs as peers in one canonical ownership registry.

For each lab it records:

- stable slug;
- course order;
- Foundations versus Modern-extension role;
- mechanism family;
- current public title;
- accent token;
- stable Quick Assign ID;
- current source/build ownership paths.

R0 does not pretend that the implementations are already structurally unified. The `implementation.kind` field records whether the current lab is still committed-static source plus release transforms or generated source plus release transforms.

That distinction is evidence of debt to remove in later #47 phases rather than a second public product class.

### `src/product/public-artifact-sha256.json`

Contains the accepted SHA-256 digest for all 58 files generated from frozen v1.8.1 baseline `d1c72e10e6c5bf64b9a4bbed578b2305d1c988d0`.

This is the R0 equivalence oracle.

### `tools/build_current.py`

Defines the current build entry point for architecture work.

R0 deliberately delegates actual composition to `tools/build_site_v1_8_1.py`. It then:

1. validates the canonical release boundary;
2. validates all fifteen canonical lab owners and source paths;
3. cross-checks stable Quick Assign IDs and EN/ZH/VI/ES assignment coverage;
4. runs the inherited current v1.8.1 builder;
5. compares canonical lab title/course-order/accent metadata against the emitted 15-row `applets.json`;
6. verifies each declared public lab path exists;
7. computes all generated file hashes;
8. fails if any output file is added, removed, or byte-different from the frozen oracle;
9. writes machine-readable evidence under `release-evidence/v1.9-canonical-source-r0.json`.

### `tools/test_v1_9_canonical_source_r0.py`

Exercises the R0 gate and self-tests the hash comparator against changed, added, and removed artifact cases.

## Why R0 does not refactor the old builder yet

The current release is assembled through multiple historical layers. Replacing several of them while simultaneously creating the source model would make a byte difference difficult to attribute.

R0 instead establishes three independent facts first:

1. what the current product is;
2. which source/build inputs currently own each lab;
3. exactly which bytes the public build must produce.

Later migrations can therefore replace one dependency at a time while the same oracle remains fixed.

## Acceptance criteria

R0 passes only when:

- the canonical product model contains exactly 15 unique labs;
- course order is exactly 1 through 15;
- track boundary is exactly 13 Foundations plus 2 Modern extensions;
- all fifteen stable Quick Assign IDs match the active registry;
- every declared current source ownership path exists;
- canonical public title, course order, and accent agree with the emitted catalogue;
- all 15 public lab files exist;
- generated artifact contains exactly the frozen 58 paths;
- every generated file SHA-256 equals the accepted baseline oracle;
- all inherited release, algorithm, localization, browser, responsive, assignment, privacy, and provenance gates still pass.

## Non-goals

R0 does not:

- change visible layout;
- normalize the modern three against the original twelve;
- alter copy or translation;
- change any algorithm;
- change Quick Assign behavior;
- change analytics;
- change deployment or publication to the new facade;
- delete historical builders;
- introduce design tokens into emitted CSS;
- claim that #47 is complete.

## Next architecture phases

### R1 — canonical public metadata ownership

Move current catalogue/release/locale ownership behind canonical current sources while retaining exact generated bytes. Historical manifests stay available for historical release reproduction but stop being the authority for current-state reasoning.

### R2 — peer lab source ownership

Give Transformer, Agent Tool Use, and Minimax peer source ownership rather than requiring current composition to reconstruct them through their release-era candidate builders. Preserve exact bytes.

### R3 — shared shell and token extraction

Extract current shared shell primitives and design tokens into canonical build-time sources. Inline them into each final self-contained applet without changing emitted bytes.

### R4 — current builder independence

Remove current `tools/build_current.py` dependence on the historical v1.8.1 → v1.8 → v1.7.2 → older release ladder. Historical builders remain frozen provenance, not current dependencies.

Only after R4 and the complete inherited Verify stack pass may #48 intentionally change visible product design.

## Evidence boundary

R0 establishes source ownership and byte equivalence. It says nothing about whether the frozen v1.8.1 visual design is optimal. The diagnostic visual census already found cross-suite inconsistencies; those remain intentionally frozen until the architecture phase makes their later correction attributable.
