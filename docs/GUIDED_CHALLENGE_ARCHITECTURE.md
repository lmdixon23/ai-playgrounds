# Guided Challenge Architecture

## Objective

AI Playgrounds should preserve rapid, direct exploration while also supporting diagnostic instruction that captures a learner prediction before the result is visible.

The proposed suite-level model has two modes.

### Explore mode

- immediate control changes;
- immediate visualization updates;
- suitable for demonstration, open inquiry, and rapid comparison.

### Guided Challenge mode

1. Present a mechanism-specific prompt.
2. Record a prediction.
3. Lock the prediction.
4. Reveal the algorithm state or output.
5. Compare expected and actual mechanisms.
6. Explain the discrepancy.
7. Transfer the reasoning to a changed case.

A prediction is not considered committed merely because a textarea exists. The interface must prevent the predicted state from being edited after reveal, while preserving it for comparison.

## Mechanism-specific prediction objects

| Applet | Diagnostic prediction object |
| --- | --- |
| Search | next frontier state or expansion order |
| Hill climbing | next candidate accepted and the comparison rule |
| Wumpus World | proven safe, possible hazard, and unresolved squares |
| CNF and SAT | forced literal, surviving branch, or contradiction source |
| Bayes rule | true-positive and false-positive counts before posterior |
| Bayesian network | update direction and conditional dependence status |
| Overfitting | training and validation error direction |
| Neural network | representational or decision-boundary change |
| KNN | selected neighbors, then predicted class |
| K-means | point assignments, then centroid movement |
| Convolution | one output-cell value before revealing the sum |
| Q-learning | selected action, TD target, and update direction |

## State contract

A guided challenge should expose the following state explicitly:

- inactive;
- awaiting prediction;
- prediction complete but unlocked;
- locked;
- revealed;
- compared;
- reset.

Controls that alter the underlying problem must either reset the challenge or require a new prediction. A revealed answer must not silently update after a parameter change while still being compared with an old prediction.

## Accessibility contract

- Every selection must be possible with keyboard input.
- Prediction and actual state must be available as text, not only color or geometry.
- The comparison must use redundant cues such as text, line style, and color.
- Live-region announcements should be concise and should not fire on every animation frame.
- Reduced-motion preference must not remove access to the state sequence.

## Localization contract

- The challenge state must survive language switching.
- Text labels may change; prediction data must not.
- New strings must be stabilized in English and reviewed in existing Chinese before Vietnamese and Spanish translation begins.
- Language changes must not reveal a locked answer or reset the challenge silently.

## R1 prototype

KNN is the first implementation because external educator feedback identified a precise diagnostic target:

- place a query point;
- predict exactly which k training points will count as nearest;
- predict the class;
- lock;
- reveal the actual neighbor set and class;
- report overlap between predicted and selected neighbors.

This prototype tests the state model without forcing every applet into the same prediction shape.

## Required regression cases for future expansion

- reveal disabled before lock;
- lock disabled until the required prediction is complete;
- locked prediction is immutable;
- parameter change resets stale prediction state;
- reset returns to inactive state;
- language switch preserves prediction data;
- keyboard can select every mechanism object;
- actual result is generated by the same algorithm path used by Explore mode;
- text comparison agrees with the visual comparison;
- share URLs do not expose private student responses.
