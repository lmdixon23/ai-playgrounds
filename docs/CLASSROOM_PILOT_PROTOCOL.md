# Classroom pilot protocol

## Purpose

Obtain bounded evidence about usability, misconception repair, and teacher adoption without conflating a pilot with an efficacy trial.

## Minimal design

- One applet and one lesson objective.
- One teacher and one intact class, or a small educator usability group.
- Pre-specified observation sheet and post-lesson exit prompt.
- No collection of names in the software or public analytics.
- Aggregate reporting; suppress small demographic or geographic cells.

## Core measures

1. Task completion for a fixed predict–run–explain sequence.
2. Error categories before and after the explanation step.
3. Teacher preparation time and points of confusion.
4. Accessibility and language barriers observed in context.
5. Whether the applet’s simplifications were understood.

## Advancement gates

Advance to a comparative study only when task completion is high, no severe misconception is introduced, the teacher can run the lesson without developer intervention, and the instrument distinguishes interface problems from conceptual errors.

## Kill conditions

Pause the pilot if student work is inadvertently transmitted, an applet gives materially incorrect feedback, the language version changes the mathematical meaning, or the observation protocol cannot separate software failure from instructional failure.
